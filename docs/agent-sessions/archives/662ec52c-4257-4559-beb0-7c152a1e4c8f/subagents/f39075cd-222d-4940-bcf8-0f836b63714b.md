### 4. How `exerciseId` is matched in history

Three established patterns:

**A. Progression chart (strict identity)** — `ExerciseProgressionChart.tsx`:

```typescript
function resolveEntryIdentity(entry: ExercicioConcluidoEntry): string {
  const rawId = entry.exerciseId?.trim().toLowerCase();
  if (rawId) return rawId;
  return (entry.nome ?? "").trim().toLowerCase();
}
// Match: resolveEntryIdentity(entry) === exerciseId
```

**B. History session rows (template-aware)** — `workoutHistory.adapter.ts` → `buildHistorySessionRows`:

```typescript
resolvedId =
  logEx.exerciseId ||
  templateByName.get(logEx.nome.toLowerCase().trim())?.id ||
  logEx.nome.toLowerCase().trim();
```

**C. Live session store (exact ID, then name)** — `workoutStore.ts` → `resolveCompletedExerciseForTarget`:

```typescript
completed.find(e => e.exerciseId === exerciseId)
// fallback: normalizeExerciseNameKey(exercicioNome)
```

For **cross-session history**, pattern **A** (`resolveEntryIdentity`) is the canonical filter. Pass `exerciseId.trim().toLowerCase()` to align with chart logic.

### Recommended approach: last 3–5 executions by `exerciseId`

**Do not add a new Firestore query** — there is no per-exercise index. Reuse already-loaded history and filter client-side.

```typescript
import type { WorkoutHistoryRecord, ExercicioConcluidoEntry } from "../services/workout.service";
import {
  resolveExecutedExercises,
  resolveRecordCompletionDateISO,
} from "../services/workoutHistory.adapter";

function resolveEntryIdentity(entry: ExercicioConcluidoEntry): string {
  const rawId = entry.exerciseId?.trim().toLowerCase();
  if (rawId) return rawId;
  return (entry.nome ?? "").trim().toLowerCase();
}

export interface ExerciseExecutionSnapshot {
  recordId: string;
  sessionDateISO: string;
  sessionTitle: string;
  entry: ExercicioConcluidoEntry;
}

export function getLastNExerciseExecutions(
  records: WorkoutHistoryRecord[],  // already newest-first from fetch
  exerciseId: string,
  limit = 5
): ExerciseExecutionSnapshot[] {
  const target = exerciseId.trim().toLowerCase();
  const out: ExerciseExecutionSnapshot[] = [];

  for (const record of records) {
    if (out.length >= limit) break;

    const matching = resolveExecutedExercises(record).filter(
      (entry) => entry?.nome?.trim() && resolveEntryIdentity(entry) === target
    );
    if (matching.length === 0) continue;

    out.push({
      recordId: record.id,
      sessionDateISO:
        resolveRecordCompletionDateISO(record) ?? record.dataISO?.slice(0, 10) ?? "",
      sessionTitle: record.titulo ?? record.sessaoId ?? "Treino",
      entry: matching[0], // one entry per session; bi-set: filter already scoped by exerciseId
    });
  }

  return out;
}
```

**Integration steps:**

1. **Data source:** `const { records, fetchNextPage, hasNextPage } = useWorkoutHistoryInfinite()` (same as Progress screen).
2. **Pagination:** If `records` may not cover 5 sessions, call `fetchNextPage()` until `getLastNExerciseExecutions(...).length >= limit` or `!hasNextPage`.
3. **Placement:** Add helper to `workoutHistory.adapter.ts` or extract shared `resolveEntryIdentity` from `ExerciseProgressionChart.tsx` to avoid duplication.
4. **UI:** New lightweight modal/sheet in `workout-session.tsx` — no existing quick modal to reuse; `WorkoutHistoryModal` is session-level only.
5. **Bi-sets / tri-sets:** Filter by **active** `exerciseId` only (per `.cursorrules` state bleed prevention).

**Optional enhancement:** If template exercises are available, normalize the target ID through `buildHistorySessionRows(record, templateExercicios)` for legacy records missing `exerciseId`.
