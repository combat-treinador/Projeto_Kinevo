## Data flow (Firebase → UI)

```
Firestore workouts (all docs, no limit)
  → selectValidWorkoutAssignmentsByBiblioteca()  [multi-plan]
  → subscribeActiveWorkoutPlans / fetchAllActivePlans
  → React Query key "allActivePlans"  { plans: TodayPlanResponse[] }
  → useAllActivePlans()
       ├─ plans[]          (full array — used only in Progress)
       └─ activePlan       (single object = plans[0] or lastPlanId match)
  → Home + Plans screens consume activePlan only
```

Firebase fetch is **not** limited to one plan. The collapse happens in hooks, cache, and UI.

## Root cause of regression

The Firebase layer was upgraded to multi-plan (`fetchAllActivePlans`, `selectValidWorkoutAssignmentsByBiblioteca`, `subscribeActiveWorkoutPlans`), but the consumer layer was only partially migrated:

1. **`useAllActivePlans` still exposes a singular `activePlan`** resolved as `plans[0]` (or `lastPlanId`), not user-selected plan.
2. **Home and Plans bind to `activePlan`**, so only one plan is ever shown.
3. **Legacy `todayPlan` cache path** still stores/reads `plans[0]` via `toTodayPlanResult` and `persistActivePlansResult`.
4. **No plan-switcher UI** exists in `plans.tsx` or Home (despite FAQ copy promising one).
5. **`syncPlanFromServer(rawPlans[0])`** in `useAllActivePlans` (lines 99–101) can overwrite `activePlanId` with the first fetched plan on every snapshot.

Fetch is fine; display/selection is broken.
